# CRM קליניקת אורה

זה הזיכרון הקבוע של הפרויקט. קוראים אותו לפני כל שלב עבודה.
מקור האמת לדרישות: האפיון `exam/q2-prd-final.html`.

## 1. מה המערכת ועבור איזה עסק

**העסק:** קליניקת אורה, קליניקה לטיפולי פנים ואסתטיקה ברחוב סוקולוב 48 בהרצליה.
- רותם ברנע: הבעלים והמנהלת.
- ליאת כהן: מטפלת, לייזר.
- נטע אדרי: מטפלת, בוטוקס וחומצה.

**הבעיה:** פרטי הלקוחות, התורים והפניות מפוזרים בכמה מקומות.
- יש כפילויות, ופניות הולכות לאיבוד.
- לרותם אין תמונת מצב.
- נתוני הקליניקה: 40-50 פניות בשבוע, רק כ-30% קובעות טיפול ניסיון, וכ-35% מבריזות.

**המערכת:** CRM פנימי לצוות בלבד. לקוחות הקליניקה לא משתמשות בו. המערכת בעברית ומותאמת קודם כול לטלפון.
- כל לקוחה מזוהה לפי מספר הטלפון.
- כל תור וכל קריאת שירות מקושרים לכרטיס של הלקוחה.
- לכל קריאה יש סטטוס ואחראית.
- המסך הראשי מראה מה פתוח, מה בטיפול ומי אחראית.

**מודולים:**
- חובה: דשבורד, לקוחות, תורים, קריאות שירות.
- ניהול צוות והרשאות.
- חדשים:
  - יומן תורים ויזואלי
  - המשימות שלי והתראות שיוך
  - תורים למחר עם תזכורת וואטסאפ ידנית
  - מקור הגעה ואחוז המרה

**לא בגרסה הזו:** יומן חיצוני, סליקה, אימיילים ותזמון אוטומטי.

## 2. כללי עבודה קבועים

### סטאק
- **Next.js עם TypeScript.**
- **Supabase** למסד הנתונים (Postgres), להתחברות (Auth) ולהרשאות (RLS).
- **פריסה ל-Vercel**, עם שמירת גרסה ב-GitHub.

### שפה וכיוון
- הממשק כולו בעברית ובכיוון RTL: `<html lang="he" dir="rtl">`.
- סרגל הצד נמצא בצד ימין, והחיצים מתהפכים.
- טלפונים, תאריכים ושעות נשארים בסדר הרגיל שלהם בתוך הטקסט.
- הנוסח בממשק פונה בלשון נקבה, כי כל הצוות נשים ("צרי לקוחה חדשה", "נסי שוב").

### שמות
- שמות של טבלאות, שדות וערכי רשימה: באנגלית, ב-snake_case. לדוגמה: `service_requests`, `in_progress`.
- כל הכותרות והתוויות בתצוגה: בעברית. התרגום מופיע בעמודת "תווית" בטבלאות שבסעיף 3.

### שדות בחירה
- כל שדה בחירה הוא רשימה סגורה עם ערכים מוגדרים. אף פעם לא טקסט חופשי.
- רשימה קבועה נשמרת כ-enum במסד הנתונים.
- רשימה שמשתנה (מטפלת, טיפול, אחראית) נבחרת מתוך טבלה אחרת.

### שדות חובה בכל טבלה
- לכל טבלה יש `id` (uuid), `created_at` ו-`updated_at`.
- `updated_at` מתעדכן אוטומטית בכל שינוי.

### אבטחה
- שום מפתח או סיסמה לא נמצאים בקוד. רק במשתני סביבה: `.env.local` במחשב, והגדרות הסביבה ב-Vercel.
- `.env.local` נמצא ב-`.gitignore` ולא עולה ל-GitHub.
- מפתח השירות של Supabase (service role) משמש רק בצד השרת, ואף פעם לא בדפדפן.
- ההרשאות נאכפות במסד הנתונים (RLS), לא רק בהסתרת כפתורים.

### דרך עבודה
- עובדים שלב אחרי שלב, ולא מתחילים שלב בלי אישור של ענבל.
- לפני כל שלב שומרים גרסה:
  - העותק נשמר בתיקייה `versions/`.
  - הגרסה נרשמת ב-`VERSIONS.md`.
- כל שינוי במסד הנתונים הוא קובץ מיגרציה ממוספר ב-`supabase/migrations/`, עם קובץ ביטול `_down.sql`.

## 3. האובייקטים, השדות והקשרים

שש טבלאות. הלקוחה במרכז: כל תור וכל קריאת שירות מקושרים ללקוחה.
אחוז המרה, "התור הבא" וסימון 48 שעות מחושבים מהנתונים, ואין להם טבלה.
השמות כאן הם השמות במסד הנתונים, והם מחליפים שמות ישנים שמופיעים באפיון (למשל `staff_id` הוא כאן `therapist_id`).

### staff (צוות)
| שדה | סוג | תווית | הערה |
|---|---|---|---|
| id | uuid, PK | | זהה למשתמשת ב-Supabase Auth |
| full_name | text | שם מלא | חובה |
| email | text | אימייל | ייחודי, אימייל ההתחברות |
| role | enum | תפקיד | `manager` = מנהלת, `therapist` = מטפלת |
| is_active | boolean | סטטוס | `true` = פעילה, `false` = מושבתת. מושבתת לא נכנסת ולא מופיעה בשיוך |
| created_at | timestamptz | נוצרה | אוטומטי |
| updated_at | timestamptz | עודכנה | ⚠️ עוד לא קיים במסד |

### clients (לקוחות)
| שדה | סוג | תווית | הערה |
|---|---|---|---|
| id | uuid, PK | | |

| phone | text | טלפון | חובה וייחודי. נשמר מנורמל: בלי מקפים ורווחים, ו-`+972` הופך ל-`0` |
| source | enum | מקור הגעה | `instagram` = אינסטגרם, `facebook` = פייסבוק, `website` = אתר, `referral` = המלצה, `other` = אחר |

| created_at, updated_at | timestamptz | נוצרה, עודכנה | אוטומטי |

### treatments (מחירון)
| שדה | סוג | תווית | הערה |

### appointments (תורים)
| שדה | סוג | תווית | הערה |
|---|---|---|---|
| id | uuid, PK | | |
| client_id | uuid → clients | לקוחה | חובה |
| treatment_id | uuid → treatments | טיפול | חובה |

| status | enum | סטטוס | `upcoming` = עתידי (ברירת מחדל), `done` = בוצע, `cancelled` = בוטל |
| notes | text | הערות | לא חובה |
| created_by | uuid → staff | נקבע על ידי | אוטומטי |

### service_requests (קריאות שירות)
| שדה | סוג | תווית | הערה |
|---|---|---|---|
| id | uuid, PK | | |

| created_at | timestamptz | נפתחה | אוטומטי. ממנו מחשבים את סימון 48 השעות |

| closed_at | timestamptz | נסגרה | נקבע בסגירה, ומתנקה כשפותחים מחדש |

### notifications (התראות שיוך)
| שדה | סוג | תווית | הערה |
|---|---|---|---|
| id | uuid, PK | | |
| recipient_id | uuid → staff | למי | |
| request_id | uuid → service_requests | קריאה | |
| message | text | הודעה | נוצרת אוטומטית, למשל "רותם שייכה אלייך קריאה: דנה לוי" |
| is_read | boolean | נקראה | ברירת מחדל false |
| created_at | timestamptz | | אוטומטי |
| updated_at | timestamptz | | ⚠️ עוד לא קיים במסד |

### קשרים
- לקוחה אחת ← הרבה תורים.
- לקוחה אחת ← הרבה קריאות שירות.
- טיפול אחד ← הרבה תורים.
- מטפלת אחת ← הרבה תורים.
- חברת צוות אחת ← הרבה קריאות שירות (כאחראית).
- קריאה אחת ← הרבה התראות.
- חברת צוות אחת ← הרבה התראות.

```
staff ──< appointments >── clients ──< service_requests ──< notifications >── staff
            │                              │
treatments ─┘                     staff ───┘ (assigned_to)
```

### פער פתוח מול המסד
לפי הכלל "לכל טבלה יש `updated_at`", צריך להוסיף את השדות הבאים במיגרציה הבאה, באישור:
- `staff.updated_at`
- `treatments.created_at` ו-`treatments.updated_at`
- `notifications.updated_at`

## 4. הרשאות וכללים עסקיים

| פעולה | מנהלת (רותם) | מטפלת (ליאת, נטע) |
|---|---|---|
| צפייה, יצירה ועריכה של לקוחות, תורים וקריאות | ✓ | ✓ |
| שיוך קריאה | לכל אחת | רק לעצמה |
| דשבורד | כל הצוות | ברירת מחדל: שלי |
| מחיקת רשומות | ✓ | ✕ |
| ניהול צוות ומחירון | ✓ | ✕ |

### נאכף כבר במסד הנתונים
- אין שני תורים חופפים לאותה מטפלת. תור שבוטל לא נחשב.
- תור נקבע רק בשעות הפעילות: א'-ה' 09:00-19:00 ו-ו' 09:00-13:00. הטיפול צריך להסתיים עד הסגירה.
- הטלפון ייחודי ומנורמל.
- אין "בטיפול" בלי אחראית.
- שיוך רק לאשת צוות פעילה. מטפלת משייכת רק לעצמה.
- לקוחה שיש לה תורים או קריאות לא נמחקת.
- RLS על כל הטבלאות:
  - משתמשת מושבתת, או מי שלא מחוברת, לא רואה כלום.
  - כל אחת רואה רק את ההתראות שלה.

### נשאר לשלב האוטומציות
- `updated_at` מתעדכן אוטומטית.
- `closed_at` נקבע בסגירת קריאה ומתנקה בפתיחה מחדש.
- התראה נוצרת כשמשייכים קריאה למישהי אחרת. אין התראה כשמשייכים לעצמך.
- אפשר לסמן תור כ"בוצע" רק אחרי מועד התור.
- משך ומחיר מועתקים מהמחירון.

### מחושב בתצוגה
- **התור הבא:** התור הקרוב בעתיד שלא בוטל.
- **קריאה ותיקה:** קריאה שלא נסגרה ונפתחה לפני יותר מ-48 שעות. מסומנת באדום.
- **אחוז המרה:** לקוחות שקבעו לפחות תור אחד, חלקי כל הלקוחות, לפי מקור הגעה.

## 5. מראה הממשק (מוגדר באפיון)

**אווירה:** רך, חם ויוקרתי. כרטיסים לבנים שצפים על רקע שמנת.

- גדלים: כותרת עמוד 30, KPI 28, מקטע 18, כרטיס 16, גוף 14, טקסט משני וכפתורים 12.

### רכיבים
- **כפתור ראשי:** אחד בכל מסך.
  - רקע `#E3BFA8` וטקסט `#2C2520` ב-Semibold. הטקסט אף פעם לא לבן.
  - גובה 40px, צורת pill.
- **כפתור משני:** רקע `#F1D6D0`, בלי מסגרת.
- **כפתור מושבת:** שקיפות 50%.
- **כפתור בטעינה:** ספינר קטן, והטקסט נשאר.
- **פינות:**
  - כרטיסים: 24px.
  - שדות ושורות: 16px.
  - כפתורים ותגיות: pill.
  - מיכל האפליקציה: 32px.
- **צללים:** הגוון מבוסס על צבע הטקסט.
  - כרטיס: `0 8px 30px rgba(44,37,32,.06)`.
  - hover ומודאל: `0 16px 48px rgba(44,37,32,.10)`.
- **שדות:**
  - גובה 44px, מסגרת 1px `#EDE5DC`.
  - שגיאה מוצגת ליד השדה, ב-`#B5533C`.
  - Focus: מסגרת 2px `#A67C52`.
- **אייקונים:** קוויים בעובי 1.5px, בברונזה. 20px בניווט, 24px באריחים.
- **ריווח:** רשת 8px, ו-24px בין כרטיסים. שורת טבלה בגובה 48px.

| מסך | נתיב | גישה |
|---|---|---|
| כניסה | `/login` | פתוח |

- **מחשב:** תפריט צד קבוע בצד ימין.
- **נייד (מתחת ל-768px):** סרגל תחתון עם 4 לשוניות: ראשי, לקוחות, תורים, קריאות. הטבלאות הופכות לכרטיסים.
- **כותרת עליונה בכל מסך:** חיפוש לפי טלפון, ופעמון התראות עם מונה.
- **באדג' "חדש"** ליד "קריאות" בתפריט.
- **כפתור "+" צף** ליצירת לקוחה, תור או קריאה.
- משתמשת לא מחוברת מופנית למסך הכניסה.

### חוויית משתמש
- **מובייל קודם:** מ-375px. אזורי מגע של 44px לפחות. בלי גלילה לרוחב. שדה טלפון פותח מקלדת מספרית.
- **Toast** אחרי כל שמירה: "הלקוחה נשמרה", "התור נקבע", "הקריאה נפתחה".
- **Optimistic UI:** שינוי סטטוס מתעדכן מיד, וחוזר אחורה עם הודעת שגיאה אם השמירה נכשלה.
- **טעינה:** Skeleton במקום ספינר.
- **אנימציות:** עד 200ms.
- **מצבים ריקים** מציעים פעולה, למשל "לא נמצאה לקוחה עם הטלפון הזה" יחד עם "צרי לקוחה חדשה".
- **אישור לפני ביטול או מחיקה:** למשל "לבטל את התור של דנה ביום ג'?".
- **מקלדת:** Tab עובר בין השדות לפי הסדר, Enter שומר ו-Esc סוגר מודאל.

## 6. נקודות רגישות
- **appointments:** מניעת חפיפה ואזור זמן, כולל שעון קיץ.
- **staff:** הטבלה מחוברת ל-Auth, וכל ההרשאות תלויות בה.
  - הזמנת משתמשת דורשת את מפתח השירות.
  - המפתח נשמר רק במשתני סביבה בצד השרת.
- **notifications:** לבנות אחרונה, כי שום דבר אחר לא תלוי בה.
